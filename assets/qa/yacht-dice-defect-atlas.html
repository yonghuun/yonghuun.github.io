아직 안 고친 것

권하는 순서는 D1 → D3. D3은 C19·C20을 근본적으로 불필요하게 만든다. 보안 관련 1건은 공개본에서 제외했다.

  • D1
    RoomController의 catch-all → 404모든 IllegalArgumentException이 “방 없음”으로 위장돼 디버깅이 막힌다. NumberFormatException까지 404가 된다.
  • D3
    RoundState가 인메모리재시작하면 진행 중 게임 전부 유실. 포트가 이미 분리돼 있어 Redis 어댑터만 추가하면 된다.
  • D4
    UserService.assignRoom의 Map.of NPE 가능hostId가 null이면 500. 코드상 가능, 재현 미확인.
  • D5
    JOIN Lua의 return 4 미처리“이미 명단에 있음”이 성공으로 취급돼 카운터가 드리프트한다.

미검증으로 남은 것 — 실기기 재현 3종(이어하기 404 · 재접속 굴림 · 마감 자동 굴림), Docker 통합 테스트 5건, TOUCH Lua 실측.

버그에서 역산한 규칙 8

다음에 이 코드를 만질 때 알고 있어야 하는 것들.

  1. 설계턴 진행의 판단은 advanceTurn 한 곳에만 — 제출 경로와 마감 만료 경로가 같은 코드를 지나야 갈라지지 않는다.
  2. 설계게임 종료는 GameCompletionService 한 곳. 순서가 중요하다: 타이머 정지 → phase CAS 전이 → 방송.
  3. 설계굴림 횟수·주사위·KEEP의 권위는 서버. 클라는 받아 쓴다.
  4. 설계방 존재의 권위는 Redis. WS도 이제 여기에 물어본다.
  5. 프로세스CI에 백엔드 테스트를 게이트로 건다 — “실패 0건”과 “실행 0건”은 로그에서 똑같이 조용하다.
  6. 프로세스main·develop에 직접 머지하지 않는다. 여기엔 기술적 방어책이 없다.
  7. 프로세스레이아웃은 최소재현과 최악치 양쪽으로 실측한다(6자/12자, 2인/6인).
  8. 프로세스고치지 않기로 한 것도 근거와 함께 남긴다 — 기획 결정과 구현 결정을 섞지 않는다.
