## 매초 tick을 보내면 생기는 문제

서버가 모든 방의 모든 사용자에게 매초 남은 시간을 보내면 접속자와 방이 늘수록 메시지 수도 함께 증가합니다. 화면에 숫자 하나를 표시하기 위해 지속적인 브로드캐스트가 필요하고, 네트워크 지연으로 사용자마다 tick 도착 시점도 달라질 수 있습니다.

## deadline을 한 번 전달하기

`round.start` 이벤트에 라운드 종료 시각인 deadline epoch ms를 담아 전달하도록 설계했습니다. 클라이언트는 `deadline - 현재 시각`으로 남은 시간을 계산하고 화면을 갱신합니다.

클라이언트 타이머는 표시 용도입니다. 제출 허용 여부와 라운드 종료의 최종 판정 권한은 서버가 가집니다. 브라우저 타이머가 백그라운드 탭에서 지연되거나 네트워크가 잠시 느려져도 게임 규칙은 서버 시간을 기준으로 유지됩니다.

## 재접속과 오차

재접속한 사용자에게는 현재 라운드 상태와 동일한 deadline을 다시 전달합니다. 클라이언트는 수신 즉시 남은 시간을 다시 계산하므로 매초 tick 이력을 복구할 필요가 없습니다.

네트워크 왕복 지연과 브라우저 타이머 오차는 표시 시간에 작은 차이를 만들 수 있습니다. 시스템 시간이 크게 다른 클라이언트에 대해서는 향후 서버 시각과 왕복 시간을 여러 번 측정해 offset을 보정하는 방식을 검토하고 있습니다.

## 정리

deadline 방식은 메시지 수를 줄이면서도 서버 중심 판정을 유지합니다. 다만 실제 네트워크 환경에서 재접속, 지연, 시스템 시간 오차를 반복 검증하는 작업이 남아 있습니다.
